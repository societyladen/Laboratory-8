## Планировщик задач

### Текст задачи

Разработать консольное приложение с дружественным интерфейсом с возможностью выбора заданий для работы с «базой данных (БД)», хранящейся в бинарном файле. Перечень полей (минимум 5), достаточно полно характеризующих заданную в варианте предметную область, предложить самостоятельно (постараться отразить в перечне полей такие, которые требуют разных типов данных). Приложение должно выполнять следующие функции:

1. Чтение базы данных из бинарного файла.
2. Просмотр базы данных.
3. Удаление элементов (по ключу).
4. Добавление элементов.
5. Реализация 4 запросов (формулировки запросов придумать самостоятельно). 2 запроса должны возвращать перечень, 2 запроса одно значение.

В классе должны присутствовать свойства, конструкторы, перегруженный метод ToString(). Весь функционал приложения реализовать в виде методов вспомогательного класса с помощью LINQ-запросов. Предусмотреть обработку возможных ошибок при работе программы.

Выбрана предметная область – **«Планировщик задач»** со следующими полями, характеризующими каждую задачу:

- ID задачи (целое число, уникальный идентификатор)
- Название задачи (строка)
- Приоритет (целое число, 1 – низкий, 2 – средний, 3 – высокий)
- Длительность (вещественное число, часы от 0.1 до 24)
- Статус выполнения (логический тип, выполнено/не выполнено)

### Алгоритм решения

Программа представляет собой консольное приложение для ведения базы данных задач (планировщик), которая хранится в бинарном файле.

**Класс Database** начинается с объявления пяти приватных полей, соответствующих характеристикам задачи: `_id` (ID задачи, целое число), `_title` (название, строка), `_priority` (приоритет, целое число 1-3), `_duration` (длительность, вещественное число), `_isCompleted` (статус выполнения, логический тип). Для доступа к этим полям определены публичные свойства только для чтения. Конструктор класса принимает пять параметров и инициализирует соответствующие приватные поля. Перегруженный метод `ToString()` возвращает строковое представление задачи, преобразуя числовые значения в читаемый вид (например, приоритет 3 отображается как "Высокий", статус `true` как "Выполнено").

**Метод FillBinaryFile** отвечает за создание и заполнение бинарного файла тестовыми данными. Внутри метода создаются массивы названий задач, приоритетов, длительностей и статусов выполнения. С помощью `BinaryWriter` в цикле для каждой задачи последовательно записываются все пять полей в файл в определённом порядке: сначала целое число (ID), затем строка (название), затем целое число (приоритет), затем вещественное число (длительность) и в конце логическое значение (статус выполнения). Важно, что порядок записи должен строго соблюдаться при чтении. Если файл уже существует и не пуст, метод не перезаписывает его, сохраняя данные пользователя.

**Метод ReadFilePath** выполняет чтение бинарного файла и восстановление списка объектов. Сначала проверяется существование файла, затем с помощью `BinaryReader` в цикле, пока не достигнут конец файла, последовательно считываются данные в том же порядке, в котором они записывались: ID, название, приоритет, длительность, статус выполнения. Каждый прочитанный набор данных преобразуется в объект `Database` и добавляется в список `tasks`, который возвращается вызывающему коду. При возникновении ошибок чтения (например, если файл повреждён или имеет неверный формат) исключение перехватывается и выводится сообщение об ошибке.

**Метод PrintAll** отвечает за вывод всей базы данных в консоль в виде таблицы. Он проверяет, не пуст ли список задач, затем выводит заголовки колонок и для каждой задачи формирует строку с её данными, преобразуя числовой приоритет в текст ("Высокий", "Средний", "Низкий") и логическое значение статуса в "Выполнено" или "Не выполнено". В конце выводится общее количество записей в базе данных.

**Метод удаления элементов** реализован в двух вариантах. `DeleteTaskByIndex` удаляет задачу по указанному индексу в списке после проверки корректности индекса (индекс не должен быть отрицательным или превышать размер списка). `DeleteTaskByIndexInteractive` является обёрткой для удобного взаимодействия с пользователем: сначала выводится нумерованный список всех задач с их названиями и ID, затем пользователь вводит номер удаляемой задачи, после чего вызывается первый метод для фактического удаления. В случае успешного удаления выводится сообщение с названием удалённой задачи.

**Метод AddTask** добавляет новую задачу в базу данных. Сначала вычисляется новый уникальный ID путём поиска максимального существующего ID в списке и прибавления единицы (этот подход предпочтительнее простого `tasks.Count + 1`, так как после удаления задач могут возникать конфликты ID). Затем метод запрашивает у пользователя название задачи, приоритет (1-3), длительность (0.1-24 часа) и статус выполнения с использованием методов валидации из класса `CheckRead`. Созданный объект добавляется в список, после чего выводится сообщение об успешном добавлении с присвоенным ID.

**Четыре LINQ-запроса** реализованы в виде отдельных методов:

1. `GetHighPriorityTasks` – возвращает перечень задач с высоким приоритетом (приоритет = 3). Использует синтаксис запросов SQL-стиля: `from t in tasks where t.Priority == 3 select t`.

2. `GetUncompletedTasks` – возвращает перечень невыполненных задач (статус = false). Также использует синтаксис запросов: `from t in tasks where t.IsCompleted == false select t`.

3. `GetTotalDuration` – возвращает одно значение – общую длительность всех задач. Использует метод `Sum()`: `tasks.Sum(t => t.Duration)`. Если список задач пуст, `Sum()` возвращает 0 (без ошибки).

4. `CountCompletedTasks` – возвращает одно значение – количество выполненных задач. Использует метод `Count()`: `tasks.Count(t => t.IsCompleted == true)`.

Все LINQ-запросы написаны в синтаксисе запросов (SQL-стиль) там, где это возможно, и с использованием методов там, где это необходимо (например, `Sum()`, `Count()`).

**Класс CheckRead** содержит статические методы для безопасного ввода данных. `ReadPath` запрашивает путь к файлу и проверяет его существование, повторяя запрос до тех пор, пока не будет введён корректный путь. `ReadInt` и `ReadPriority` выполняют ввод целых чисел с проверкой допустимого диапазона (приоритет от 1 до 3). `ReadDoubleScore` проверяет, что длительность находится в диапазоне от 0.1 до 24 часов. `ReadString` не позволяет ввести пустую строку. `ReadBool` преобразует ответы "да/нет" в логическое значение. Все методы используют циклы `while` с перехватом исключений для обработки некорректного ввода.

**Программа в классе Program** реализует главное меню с бесконечным циклом, где пользователь выбирает одно из восьми действий: просмотр базы данных (1), удаление задачи по номеру (2), добавление новой задачи (3), либо один из четырёх LINQ-запросов (4-7). Пункт 8 обеспечивает выход из программы с помощью оператора `return`. После каждого действия цикл повторяется. При вводе некорректного номера выводится сообщение об ошибке. Весь пользовательский ввод проходит через методы валидации класса `CheckRead`, что обеспечивает корректную работу программы даже при ошибочных действиях пользователя.
